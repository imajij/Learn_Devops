### frontend -> backend (both on ajij-frontend-net): works, by container name via Docker's DNS
$ docker exec ajij-frontend ping -c 2 ajij-backend
PING ajij-backend (172.30.1.3): 56 data bytes
64 bytes from 172.30.1.3: seq=0 ttl=64 time=0.141 ms
64 bytes from 172.30.1.3: seq=1 ttl=64 time=0.087 ms

--- ajij-backend ping statistics ---
2 packets transmitted, 2 packets received, 0% packet loss
round-trip min/avg/max = 0.087/0.114/0.141 ms
### (the backend runs no web server, so 'Connection refused' still proves the packet reached it)
$ docker exec ajij-frontend wget -qO- --timeout=3 http://ajij-backend
wget: can't connect to remote host (172.30.1.3): Connection refused
### backend -> frontend: HTTP to nginx works
$ docker exec ajij-backend wget -qO- http://ajij-frontend | grep -o '<title>.*</title>'
<title>Welcome to nginx!</title>
### backend -> database (both on ajij-backend-net): TCP 3306 open, real SQL query works
$ docker exec ajij-backend nc -zv -w 3 ajij-database 3306
ajij-database (172.30.2.3:3306) open
$ docker exec ajij-backend mariadb -h ajij-database -uroot -plabpass --skip-ssl -e 'SELECT @@hostname AS db_host, VERSION() AS version; SHOW DATABASES LIKE "school";'
db_host	version
ec18bb170774	8.4.11
Database (school)
school
### frontend -> database (no shared network): isolated
$ docker exec ajij-frontend ping -c 2 -W 2 ajij-database
ping: bad address 'ajij-database'
$ docker exec ajij-frontend ping -c 2 -W 2 172.30.2.3
PING 172.30.2.3 (172.30.2.3): 56 data bytes

--- 172.30.2.3 ping statistics ---
2 packets transmitted, 0 packets received, 100% packet loss
$ docker exec ajij-frontend nc -zv -w 3 172.30.2.3 3306
nc: 172.30.2.3 (172.30.2.3:3306): Operation timed out
### the database network is internal (no gateway to the outside world)
$ docker network inspect -f '{{.Name}} internal={{.Internal}} subnet={{range .IPAM.Config}}{{.Subnet}}{{end}}' ajij-frontend-net ajij-backend-net ajij-database-net
ajij-frontend-net internal=false subnet=172.30.1.0/24
ajij-backend-net internal=false subnet=172.30.2.0/24
ajij-database-net internal=true subnet=172.30.3.0/24
